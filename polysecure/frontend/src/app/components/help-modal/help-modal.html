Como usar o PolySecure

@if (activeTab() === 'standard') {

O modo SQL Padrão aceita SQL convencional (dialeto PostgreSQL). Antes de executar, o PolySecure tenta traduzir a query para SQL-Poly:

  • Tabela com prefixo store.tabela (ex.: pg.users) passa direto, igual ao modo SQL-Poly — inclusive JOIN escrito manualmente entre stores.
  • Tabela sem prefixo que seja o nome lógico de uma CREATE POLYSTORE TABLE é resolvida automaticamente pelo catálogo: se estiver em uma única store, o prefixo é adicionado sozinho; se estiver distribuída em várias stores, o PolySecure gera o JOIN cross-store por conta própria (pela chave primária).
  • Clique em "Ver SQL-Poly" na barra de ferramentas do editor para visualizar a tradução antes de executar.

Selecionar dados

-- Com prefixo de store (passa direto para o engine)
SELECT * FROM pg.users;
SELECT id, name FROM pg.users WHERE active = true;

-- Com alias de tabela
SELECT u.id, u.name
FROM pg.users u
WHERE u.id = 1;

-- Sem prefixo: "orders" é o nome lógico de uma POLYSTORE TABLE.
-- Se "orders" estiver distribuída em pg + mg, o JOIN é gerado automaticamente.
SELECT * FROM orders WHERE total > 100
ORDER BY total DESC LIMIT 10;
GROUP BY/HAVING e funções de agregação (COUNT, SUM...) não são preservados quando a tabela é resolvida sem prefixo pelo catálogo — nesse caso, use o modo SQL-Poly ou qualifique a tabela com store.tabela diretamente.

Convenções

  • O prefixo (pg, mg, neo...) é o nome da store registrada.
  • Se a query não puder ser traduzida (sintaxe já é SQL-Poly, ou tabela desconhecida), ela é enviada sem alteração para o engine SQL-Poly.
  • Para controle total sobre JOIN, DDL, DML e agregações cross-store, use o modo SQL-Poly.
} @if (activeTab() === 'poly') {

O modo SQL-Poly é a linguagem nativa do PolySecure. Suporta JOIN entre stores diferentes, DDL e DML cross-store.

SELECT cross-store

-- JOIN entre PostgreSQL e MongoDB
SELECT u.name, p.bio
FROM pg.users u
JOIN mg.profiles p ON u.id = p.user_id
WHERE u.active = true;

Operadores no WHERE

WHERE preco >= 10 AND preco <= 100
WHERE status IN ('ativo', 'pendente')
WHERE status NOT IN ('cancelado')
WHERE descricao IS NULL
WHERE descricao IS NOT NULL
WHERE nome LIKE 'Prod%'
WHERE nome NOT LIKE 'Teste%'
WHERE preco BETWEEN 10 AND 50
WHERE NOT (ativo = true)

Agregação, ordenação e paginação

-- GROUP BY / HAVING com funções de agregação: COUNT, SUM, AVG, MIN, MAX
SELECT categoria, COUNT(*) AS total, AVG(preco) AS preco_medio
FROM pg.produtos
GROUP BY categoria
HAVING COUNT(*) > 5
ORDER BY total DESC
LIMIT 10 OFFSET 0;

UNION / EXCEPT

SELECT nome FROM pg.clientes
UNION
SELECT nome FROM mg.leads;

SELECT id FROM pg.produtos
EXCEPT
SELECT id FROM pg.produtos_descontinuados;

INSERT ... SELECT cross-store

-- Copia o resultado de um SELECT para tabelas físicas em outras stores
-- (sem VALUES: os valores vêm das colunas do SELECT, na mesma ordem)
INSERT INTO POLYSTORE orders_arquivo
  pg (id, total)
  mg (id, detalhes)
SELECT id, total, detalhes FROM orders WHERE total < 10;

CREATE INDEX / ALTER TABLE

CREATE INDEX idx_email ON pg.users (email);

ALTER POLYSTORE TABLE orders ADD COLUMN cupom TEXT STORE pg;
ALTER POLYSTORE TABLE orders DROP COLUMN cupom FROM STORE pg;

REGISTER STORE (via SQL, alternativa ao painel lateral)

REGISTER STORE pg POSTGRES 'localhost' 5432 'meu_banco' 'usuario' 'senha';
REGISTER STORE mg MONGODB 'localhost' 27017 'meu_banco';

DDL — Criar / Remover tabela

-- Criar tabela distribuída em múltiplas stores
CREATE POLYSTORE TABLE orders (
  id       INT      STORE pg PRIMARY KEY,
  detalhes DOCUMENT STORE mg,
  grafo    GRAPH    STORE neo
);

-- Remover tabela
DROP POLYSTORE TABLE orders;

DML — Inserir, Atualizar, Deletar

-- INSERT em múltiplas stores simultaneamente
INSERT INTO POLYSTORE orders
  pg (id, total)    VALUES (1, 150.0)
  mg (id, detalhes) VALUES (1, 'descricao do produto');

-- Não precisa de CREATE POLYSTORE TABLE antes: INSERT INTO POLYSTORE já grava
-- direto nas tabelas físicas de cada store. Se o nome físico for diferente do
-- nome lógico da tabela polystore, indique com "store.tabela_fisica(...)":
INSERT INTO POLYSTORE produtos
  mariadb (id, preco)          VALUES (1, 10.0)
  fb.FB_PRODUTOS (id, valor)   VALUES (1, 20.0);

-- UPDATE cross-store (atualiza pg e mg de uma vez)
UPDATE POLYSTORE orders
  SET pg.total = 199.9,
      mg.detalhes = 'atualizado'
  WHERE id = 1;

-- O prefixo do SET é o nome da STORE, não um alias — não declare
-- "UPDATE mariadb.produtos p" nem use "p." no SET, o parser rejeita.
-- Se o nome físico for diferente do nome lógico, use "store.tabela_fisica.coluna":
UPDATE POLYSTORE produtos
  SET mariadb.preco          = 199.9,
      fb.FB_PRODUTOS.valor   = 655.99
  WHERE id = 1;

-- DELETE cross-store
DELETE FROM POLYSTORE orders WHERE id = 1;

Tipos de coluna suportados

  • INT, TEXT, FLOAT, BOOLEAN — colunas relacionais (PostgreSQL e demais stores SQL: MySQL, MariaDB, SQL Server, Oracle, Snowflake, SQLite, Firebird, Databricks, DolphinDB)
  • DOCUMENT — documento JSON (MongoDB; vira JSONB no Postgres)
  • GRAPH — nó ou relação (Neo4j)
O tipo é texto livre repassado a cada adapter — tipos não reconhecidos caem no tipo padrão da store (ex.: TEXT nos adapters relacionais).

Stores podem ser adicionadas diretamente pelo painel lateral esquerdo: clique no botão + ao lado de "Stores", preencha o formulário e clique em "Adicionar". Para remover, passe o mouse sobre a store e clique em ×.

17 tipos de store são suportados hoje, agrupados no formulário como: Relacionais (PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, Snowflake, SQLite, Firebird), Analytics / Cloud (Databricks, DolphinDB), NoSQL / Grafos (MongoDB, Neo4j, Redis, Cassandra) e Busca / Streaming (Elasticsearch, Apache Solr, Apache Kafka).

Também é possível registrar via API REST usando um cliente HTTP (Postman, curl, Insomnia) ou direto no editor, em modo SQL-Poly, com REGISTER STORE (veja a aba anterior).
